## 摘要

文章从一次“修改项目”的用户请求出发，解释 Codex 为什么不只是一个大模型，而是由客户端接入、App Server、Session、Agent 主循环、上下文管理、模型客户端、工具路由与执行、状态持久化和长期记忆共同组成的 Harness。核心闭环是：准备上下文、请求模型、解析下一步动作、按权限策略执行工具、写回结果，再根据反馈决定继续、等待或结束。

文章还讨论了长任务的上下文基线与压缩、Thread/Turn/Item/Session 的状态层级、工具可见性与 StepContext、审批与沙箱、长时间进程与并发执行，以及 Skills、MCP、Hooks 和子 Agent 如何作为扩展接入主循环。

## 关键知识点

1. **模型与 Harness 分工**：模型负责判断下一步，Harness 负责组织输入、调度工具、执行真实操作、保存状态并把反馈交回模型；执行环境承载文件与进程。
2. **App Server 是统一入口**：终端、IDE 和桌面客户端通过统一接口接入 Agent 引擎，并持续接收模型增量、工具进度、文件变化和审批请求；因此交互是双向事件流，而不是一次请求/响应。
3. **Agent 主循环**：一个用户请求可以包含多个模型请求和多个工具调用。每轮通常经历上下文准备、模型请求、动作解析、审批/沙箱检查、工具执行、结果写回和继续判断。
4. **状态层级**：Thread 包含多轮任务，Turn 表示一次用户任务，Item 表示该轮中的消息、模型输出、工具调用或审批记录，Session 是运行这些状态的内部容器。
5. **StepContext 保证请求一致性**：模型请求时捕获模型设置、环境视图、MCP 绑定、工具路由和项目规则，使返回的工具调用仍按模型当时看到的工具目录解释；它不会冻结外部文件系统。
6. **上下文管理**：项目规则按目录层级发现并受读取预算约束；环境说明以基线方式维护，避免每轮重复追加；长输出应截断或摘要，工具调用与结果必须成对保留。
7. **上下文压缩的边界**：压缩服务于当前任务继续运行，不等于无损归档，也不自动生成跨任务长期记忆。当前模型窗口、持久化会话历史和长期记忆是三个不同范围。
8. **工具执行安全边界**：工具注册、工具可见性、路由处理器和最终执行器不是同一个列表；审批决定是否允许，沙箱决定资源边界，二者不能由项目文字指令互相替代。
9. **恢复与长期记忆**：持久化历史用于恢复原会话；长期记忆从已完成任务中提炼可复用经验，并在新任务中先提供导航、按需检索详情，但仍需回到当前文件和工具结果验证。
10. **扩展与多 Agent**：Skills 提供做事方法和资源，MCP 接入外部工具，Hooks 在生命周期时机介入，子 Agent 复用会话、上下文、模型循环和工具执行能力，并增加父子消息和并发控制。
